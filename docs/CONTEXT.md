## 用户想解决的问题

Chasen 日常使用 Pi 编写代码，希望减少输入需求的打字操作。最初讨论的是用 skill 串联 Ming 的语音识别、音频理解和语音合成，随后用户主动将方向改为原生 Pi 插件：

> 输入 / 命令就可以直接语音输入，然后还可以绑定一个快捷键

最新指令要求：在 `D:\MyProjects` 建立独立工作区、创建并推送 GitHub 私有仓库，记录上下文背景和插件实现 plan。本阶段先交付文档，不代表已经实现插件。

项目名采用 `pi-ming-voice`，本地目录为 `D:\MyProjects\pi-ming-voice`。

## 产品方向

用户明确提出了 `/` 命令和快捷键两种触发入口。下列细节是本轮提出的第一版设计默认值，后续开发中可根据真实交互验证调整：

- `/voice` 与可配置快捷键共用开始/停止录音动作
- 首次触发开始，再次触发结束；先做切换式录音，不做按住说话
- 显示录音时长、识别中、成功或失败状态
- 用 Ming-3.0-asr-tiny 转写后追加到 Pi 输入框，保留已有文字
- 用户查看和修改后按 Enter 发送，默认不自动提交需求
- 录音时可用 Esc 取消；识别中的取消也应中止请求并阻止迟到结果回填
- 第一版为 Windows 11 的 Pi CLI extension，不修改 Pi Agent Desktop

录音后端尚未确定，FFmpeg 是第一候选；本机查到 FFmpeg 命令不等于已验证麦克风采集。快捷键默认值和配置方式也尚未确定。

## 为什么与 Ming-3.0 活动相关

蚂蚁百灵 Ming-3.0 音频模型家族活动包含语音识别、音频理解和语音合成三个方向。用户账号定位是中文 AI Builder，真实开发者工作流比罗列发布参数更合适。

本插件可以形成清晰案例：按快捷键 → 说出中英混合开发需求 → 转写回填 → 检查术语 → 发给 Pi 执行。

中文夹英文术语、文件名和函数名是重点观察项，例如 Pi、MCP、AGENTS.md、context、token、before_agent_start。不要预先假定这些词都会识别正确，也不要未经验证重写、补全代码标识符。

## 已有资料与不能推导出的结论

Tutti 目录已有活动 Brief、A/B 候选稿、ming-voice 工具包、API 文档快照和 box 测试记录。

- A 版是中英混说录音识别对照；B 版是 skill 串联 ASR、Pi、TTS，二者仍有体验占位
- 导入测试在另一台 box 上完成，输入和声音克隆参考均为 TTS 合成音频，不是 Chasen 本人的录音
- 导入记录显示三个接口曾成功响应；这是材料作者的测试，不是本仓库的复测
- 导入记录中 UK_Charlotte 合成中文有漏句，参考音频方案改善了该样例；不能泛化为全部中文音色问题
- 导入 ASR 结果里代码标识符的下划线变成空格，因此“逐字正确”不能当作代码格式无损保证
- 接口各自成功不证明已实现实时语音对话、麦克风输入或完整 Pi 集成
- 价格、余额、免费额度未核实，不写“免费使用”或成本承诺
- 没有把工具包、音频、压缩包和外部机器上的凭据复制进本仓库
